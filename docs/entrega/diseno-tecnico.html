1. Modelo entidad-relación (DER)

El modelo tiene 19 tablas. Dieciocho pertenecen a un comercio: llevan la clave foránea comercio_id y una política de Row Level Security que impide leer o escribir filas de otro comercio (RNF-10). La tabla de indicadores económicos es la única de referencia global, compartida y de sólo lectura para la aplicación.

Figura 1. DER completo. PK: clave primaria; FK: clave foránea; UK: única. Para que el diagrama se lea, de las relaciones con comercio sólo se dibuja comercio–usuario; todas las tablas con comercio_id FK lo referencian. Versión ampliable: der.svg.

Rentabilidad (HU-03), panel (HU-04), comparador (HU-12), pérdidas por falta de stock (HU-18) y stock parado (HU-19) no tienen tablas propias: se calculan al consultar sobre productos, movimientos y precios, para que nunca muestren un dato viejo.

Restricciones relevantes del modelo:

  • Código de producto único por comercio sobre su versión normalizada (RN-05).
  • Movimientos de sólo inserción: la corrección es un ajuste que referencia al original con corrige_a_id y anulado_por_id (RN-07). El rol de la aplicación no tiene permiso para borrarlos.
  • Precios de proveedor e historial de precios de venta de sólo inserción; el costo vigente es el de la última lista del proveedor principal (RN-08).
  • Montos en decimal(14,2) y fechas con zona horaria.

2. Diagrama de clases del dominio

Muestra las entidades del dominio con sus atributos principales y las operaciones que expone su módulo de la API, las relaciones con su multiplicidad (composición cuando la parte no existe sin el todo) y las enumeraciones de estado. En el código, cada entidad es un modelo de Prisma y sus operaciones viven en el servicio del módulo NestJS correspondiente; las reglas de cálculo (márgenes, punto de reposición, variación real, puntaje de proveedores, quiebres y stock parado) son funciones puras del paquete compartido, con tests unitarios.

3. Diagrama de componentes

InventarioSmart es un monolito modular: una única API REST versionada en /api/v1 sirve a la web y a la aplicación Android sobre una base PostgreSQL compartida y aislada por comercio.
